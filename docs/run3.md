# Run 3: a stereotype vector, and where the bias is

Run 2 failed on both models. The vector learned "say unknown" rather than "avoid the stereotype", and gender BBQ had little bias left to remove (`RESULTS.md`). Run 3 tests the fix for each cause. It is still **BF16 only and validation only**, and the quantization study follows only if a vector passes here.

This plan was written before any run 3 result existed. Do not change it after seeing results. If it has to change, record the change and the reason here, and treat that run as a new one.

Start it with `bash run_experiment.sh run3`. Running that again resumes. When it finishes, it commits the results archive (only that file) and pushes it.

## 1. A vector that targets the stereotype

The run 1 and 2 vector contrasted the correct answer with a wrong named answer (`contrast: evidence`). In ambiguous questions the correct answer is always "unknown", so half the vector learned to abstain. In disambiguated questions the correct answer names the stereotyped person about half the time, so the stereotype signal cancelled.

The new vector (`contrast: stereotype`, `src/steerquant/data.py`, `stereotype_pairs`) contrasts **the other named person** with **the stereotype-consistent person**:

- **"Unknown" is never in a pair,** so the vector cannot become an abstention direction.
- **Gold is ignored.** In disambiguated questions, gold agrees with the stereotype half the time, so following evidence cancels out instead. In ambiguous questions both named answers are wrong, so what remains is the preference between them.
- **BBQ's target is already polarity-adjusted.** For a negative question it names the stereotyped group; for a non-negative question it names the other group. So "target" is the biased answer in both cases. This is checked against the data in `tests/test_run3.py`.

Everything else is unchanged from run 2: same mean-difference method and answer-token position, 128 training rows (only rows with a target), each letter position balanced, ambiguous and disambiguated contexts weighted equally, unit-normalized, strength as a fraction of the mean activation norm.

Positive strength pushes toward the non-stereotyped answer. **Negative strength pushes toward the stereotype**, so it should raise stereotyped answers. That gives a built-in check on whether the vector carries the stereotype at all (see "Diagnostics").

## 2. Where the bias is

The splits are by scenario (BBQ question template), 60/20/20 by rows, seed 42, so related questions never cross splits. Validation then gets:

| Category | Validation questions | Validation scenarios |
|---|---:|---:|
| Gender | 1,240 | 11 |
| Race | 1,400 | 10 |
| Age | 768 | 5 |
| Physical appearance | 320 | 5 |
| Religion | 240 | 4 |
| Nationality | 640 | 4 |
| Disability | 320 | 4 |
| Socioeconomic status | 1,440 | 3 |

The pass rule's confidence interval resamples whole scenarios. With 3–5 of them, an interval says almost nothing. **A category needs at least 8 validation scenarios to be dose-tested.** That rule was set from these counts, before any results, and it leaves Race and Gender:

- **Race** is the new category.
- **Gender** repeats run 2's data with the new vector. That makes it the controlled comparison: only the vector changes.

The other six categories get a **descriptive bias scan**, with only the unsteered and prompt-instruction baselines. It shows where bias exists for future work, but it chooses nothing and is not a finding.

## The pass rule

**It is unchanged from run 2** (`docs/dose-finding.md`, `src/steerquant/dose.py`), so the two contrasts are judged identically. A setting passes only if all three hold:

1. **It lowers stereotyped answers** by at least 1 percentage point from the unsteered baseline.
2. **It beats random.** At the same layer and strength, the 95% scenario-bootstrap interval of the vector minus random is entirely below zero.
3. **It stays within the limits:**
   - ambiguous and disambiguated accuracy each drop by at most 2 points;
   - unnecessary "unknown" answers rise by at most 2 points;
   - invalid and truncated answers each rise by at most 1 point.

Each verdict is PASS, FAIL or NOT_SCOREABLE, per model and category, as before.

## Diagnostics

These are reported in each `verdict.md` but never change a verdict:

- **Direction check.** The number of negative-strength settings where the vector raised stereotyped answers more than random did (interval above zero). If a stereotype vector never does this, it is not carrying the stereotype.
- **Cosine with the old vector.** During extraction, the run 2 evidence direction is computed from the same training rows, and its cosine with the new vector is recorded per layer. Near 1 would mean the new vector is still mostly an abstention direction.

## One measurement change: answer parsing

Run 2's strict parser counted "B. Can't answer" as invalid. Gemma often writes that form: in run 2, **344 of its 432 invalid answers** were a letter followed by exactly that letter's option text.

From run 3, a letter followed by **its own option's exact text** counts as that letter (`src/steerquant/metrics.py`). This allows a final period, curly apostrophes, and differences in case or spacing. Everything else stays invalid:
- a letter with a different option's text, such as "A. Unknown" when A is a person;
- explanations;
- "A or B";
- bare words.

Each answer records which form it used (`answer_format`). This applies to every run 3 condition equally. **Run 1 and run 2 scores are not rescored.**

## What a result means

- **PASS on Race or Gender** names a candidate setting for the full study on that category: INT8 and NF4, frozen selection, the test split and capability. As in run 2, a pass is not a finding. Up to 24 settings are tested per model and category with no multiple-comparison correction, and there is one random direction per layer. Look at whether neighbouring strengths and the direction check agree.
- **PASS on Gender only where run 2 failed** isolates the vector construction as the cause of run 2's failure.
- **FAIL everywhere,** with a working direction check, means the vector carries the stereotype, but pushing it does not reduce stereotyped answers within the limits.
- **FAIL everywhere, with no direction check either,** means mean-difference steering at these layers does not carry the stereotype in these models. The fallback then is the abstention study described in `RESULTS.md`, with its own pass rule written before running.

This remains exploratory. Gender's test split was seen in run 1, so a later gender test evaluation is not a fresh confirmation; Race's test split has not been touched.
